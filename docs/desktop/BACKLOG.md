## 已知问题：排布求解器对叠装件沿 Z 来回挪（活锁）

`resolveLayout` 在 40 mm 下对四工位收敛不了，**不是布局放不下，是求解器自己造的重叠**：

```
st1-rotary-1-table  z +13 (clearance) → z -13 (overlap) → z +13 → ...  直到轮数用尽
st4-rotary-1-table  同上
```

转台面在「抬起来满足间距」和「压回底座产生重叠」之间反复。为此 `layoutCompliance`
新增了 `remainingPairs`（a/b/axis/deltaMm），至少让 CLI 与界面能说清「还剩哪两对」，
而不是只说一句「没排开」。

正确修法不是禁止所有 Z 位移（实测那样会把 20 mm 的收敛也搞坏、最大可行间距从 25 掉到 5），
而是「Z 位移不得减少与其声明支撑件的间距」。这条留作后续工作，未实现。

## 已知问题（记录，不阻塞）

0. ✅ **机型截图（15–18）曾长期是同一张首页，已修**（2026-10-27）：症状是四张 PNG 字节完全相同
   （`md5 53b321ad2e…`，193,039 B / 3,236 色），而 DOM 断言全过（`MACHINE_3D_OK stations=6 actuators=12 ticks=63`、
   BOM 12 行、IO 19 行）。真因不是抓图通道，而是**流程从首页开始、始终没离开首页**：
   所有面板操作都发生在首页遮罩下面，抓到的自然是同一张首页。
   修法：① 流程开头先点 `.home-link` 离开首页（等 600ms）——这才是真因；
   ② 过程中一度加过 `ffmpeg -f x11grab` 旁路抓 X 像素，后来确认 `capturePage()` 在修掉首页那步之后
   就稳定给四张不同画面（本机连续 3 次 + CI 1 次实跑均 4 张互异），已把这层复杂度去掉，
   只保留 sha256 去重守卫：四张雷同直接报错。
   现在四张图各不相同：15 = 344,689 B / 6,893 色、16 = 377,971 B / 12,036 色、17 = 135,247 B / 2,871 色、
   18 = 125,528 B / 3,032 色；`MACHINE_SHOTS_DONE captured=4 failed=0`。

# 自然语言交互 Agent · 完整设计方案

状态：设计完成，待实现（P7）
目标：用户用中文一句话完成「查、算、改、出图、联调、同步」，不必记菜单路径；Agent 不替代界面，而是并行的快捷通道。

## 1. 设计边界

做什么：
- 理解工程语境下的中文指令（含省略、指代、单位、方言式说法）
- 调用已有模块的**结构化能力**（元件库、BOM、电气校验、成本、干涉、导出、同步、联调）
- 多步任务编排（查件 → 放置 → 校验 → 出报告）
- 解释结果（为什么报错、怎么改）

不做什么：
- 不直接操作 DOM / 不模拟鼠标点击
- 不执行 shell、不读写任意路径
- 不代替人做安全/合规决策（改线号规则、改报价策略需人确认）
- 不上传图纸或整份文档到外部模型（只发结构化摘要，可关闭）

## 2. 总体架构

```
[用户输入]
   │  聊天侧栏 / 命令面板 / @对象 / 语音(后期)
   ▼
[会话层 Session]  上下文注入 + 指代消解 + 权限
   ▼
[规划层 Planner]  意图分类 → 任务分解 → 工具序列(dry-run)
   ▼
[执行层 Executor] 工具调用 + 参数校验 + 结果聚合
   ▼
[工具层 Tools]   纯函数 API（无 UI 依赖，可单测）
   ▼
[回执层 Responder]  结构化结果 → 中文说明 + 可点击跳转 + 审计记录
```

关键约束：**工具层必须是唯一写入口**，UI 与 Agent 共用同一套 API，避免两套逻辑漂移。

## 3. 工具清单（现有 9 + 新增 6）

现有：`list_components`、`search_components`、`import_cad`、`get_bom`、`run_interference_check`、`insert_component`、`run_electrical_check`、`run_cost_report`、`undo_last`

新增：
| 工具 | 类型 | 说明 |
|---|---|---|
| `get_project_context` | 只读 | 当前机型、域、视图、选中对象、底板尺寸、单位制 |
| `place_component` | 写 | 在底板/原理图指定位置放元件（含吸附与冲突返回） |
| `run_cost_report` | 只读 | ✅ 已实现（`src/cost/agent.ts`）：硬件成本统计，见 COSTING.md 4.2 |
| `export_files` | 写 | 导出 PDF/DXF/GLB/BOM，返回文件路径 |
| `start_commission` | 写 | 启动联调序列（需确认） |

每个工具：JSON Schema 入参、结构化返回、`error.code` 可读中文、幂等键（写操作）。

## 4. 上下文注入

每次会话固定注入（不超过 2 KB）：
- 当前项目名 / 机台编号 device_no / 机型配置规模（工位数、IO 点数）
- 当前域（机械/电气）与视图（装配/选型/校核/出图/原理图/IO/电箱/底板）
- 选中对象（元件 id、位号、网格坐标）
- 最近 3 步操作（可撤销提示）
- 单位制与精度约定（mm、整数数量）
- 可用工具清单（名称 + 一句话说明，动态裁剪）

指代消解：「这个」「刚才那个」「左边的接触器」→ 优先用选中对象，其次最近操作，最后追问一次（只追问一次，避免来回）。

## 5. 意图分类与路由

一级意图（规则 + 小模型分类，不依赖大模型也能跑）：
1. 查询（有哪些、多少钱、在哪、参数是多少）
2. 计算（够不够、合不合规、成本多少、干涉没有）
3. 修改（放一个、改线号、换型号、删掉）
4. 生成（出图、出 BOM、出报告）
5. 联调（上电、跑序列、查故障）
6. 同步（上传设计包、看版本差）
7. 闲聊/超纲 → 明确说「这个我做不了」并给替代路径

多步任务：Planner 输出 `[{tool, args, why}]`，执行前展示「我准备做这 3 步」，写操作逐步确认（可设置「本次全部允许」）。

## 6. 安全与权限

- **写操作分级**：只读默认放行；影响文档的写操作需确认；影响对外系统（上传、下发 PLC）需二次确认并显示目标地址
- **路径白名单**：仅项目工作区与用户数据目录
- **审计**：每次工具调用写 `agent-audit.jsonl`（时间、工具、参数摘要、结果码），可在设置页查看/导出
- **敏感信息**：`X-Design-Key` 等凭据不出现在日志与回执里，只显示掩码
- **失败兜底**：模型故障或超时 → 降级为「只读建议」模式，不执行写操作

## 7. 模型接入

- 通道：本机 JSON-RPC `127.0.0.1:7420`（Bearer）+ MCP stdio（供外部 Agent 调用）
- 模型：可配置本地（llama.cpp / Ollama）或远程 OpenAI 兼容端点；按任务路由（分类用小模型、规划用大模型）
- 工具调用协议：OpenAI tools schema；对不支持 function calling 的模型走「JSON 文本 + 解析 + 重试一次」
- 上下文预算：系统提示 ≤1.5k tokens，工具结果按需截断（列表类只回前 20 条 + 总数）
- 离线优先：无网络时仍可用规则路由完成「查件、算成本、跑校验」这些确定性任务

## 8. 交互形态

1. **侧栏聊天**（主）：右侧抽屉，支持流式输出、工具执行进度、结果卡片（表格/图片/文件）
2. **命令面板**（快）：`Ctrl+K` 模糊搜索 + 自然语言混合，回车即执行只读命令
3. **@ 对象**：在画布/原理图上选中元件后 `@`，指令自动带上该对象
4. **语音**（后期）：本地 STT，仅对白名单指令生效
5. **主动建议**（后期）：检测到「未绑点位」「缺价」「干涉」时在状态栏提示，一键让 Agent 处理

## 9. 质量评估

固定 40 条中文用例（覆盖 7 类意图、含歧义与超纲），指标：
- 意图准确率 ≥ 95%
- 工具选择正确率 ≥ 90%
- 参数抽取准确率 ≥ 90%（编号、数量、坐标、型号）
- 多步任务完成率 ≥ 80%
- 误写率 = 0（未确认的写操作一律视为失败）

回归脚本 `npm run eval:agent`，每次改提示词或工具 schema 必须跑，结果存 `docs/desktop/eval/`。

## 10. 分期

- A（1 周）：只读问答 + 4 个查询/计算工具接入 + 侧栏聊天 + 审计
- B（1 周）：单步写操作（放件、导出）+ 确认机制 + 撤销联动
- C（2 周）：多步规划（选型→布置→校验→成本→出报告）+ 成本工具
- D（持续）：联调/同步类工具、主动建议、语音、评估集扩容

- 断网时给出明确提示，不静默失败
- 审计文件可查，凭据掩码正确
